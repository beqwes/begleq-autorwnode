# begleq-autorwnode

Один скрипт для ноды Remnawave: сначала показывает, что на сервере происходит,
потом настраивает его с нуля. Ничего ставить у себя на машину не нужно —
скрипт кладётся на сервер и запускается там.

## Запуск

```bash
bash node-setup.sh
```

Спросит `SECRET_KEY`, IP панели, порт, имя сервера и часовой пояс.
Вопросы читаются с `/dev/tty`, поэтому работает и через пайп.

Только посмотреть, ничего не меняя:

```bash
bash node-setup.sh --status-only
```

Без единого вопроса:

```bash
bash node-setup.sh --secret 'КЛЮЧ' --panel-ip 203.0.113.10 --yes
```

## Что делает

**Часть 1 — отчёт о ноде**

- кто и откуда заходил: последние входы, чужие IP помечены звёздочкой,
  последняя перезагрузка, кто в системе сейчас
- неудачные попытки входа и баны fail2ban
- контейнеры: образ, статус, число рестартов, health, время старта
- службы с автозапуском и упавшие юниты
- порты наружу: TCP полностью, случайные высокие UDP свёрнуты в одну строку
- ресурсы: аптайм, нагрузка, память, swap, диск с порогами 80 и 90 %

**Часть 2 — параметры**

Подхватывает существующий `SECRET_KEY` и предлагает оставить его.
Сам определяет SSH-порт из `SSH_CONNECTION`, чтобы правилом ufw не отрезать
себе доступ. Показывает сводку и ждёт подтверждения.

**Часть 3 — настройка, 8 шагов**

1. имя сервера, часовой пояс, NTP
2. `apt update` и обновление пакетов, базовый набор утилит
3. swap 2–4 ГБ, если его нет
4. sysctl: BBR + fq, сетевые буферы, `nofile 1048576`
5. docker (ставит, если нет) и ротация логов в `daemon.json`
6. ufw (SSH, 443 tcp/udp, 80 для certbot, порт ноды только с IP панели) и fail2ban
7. `/opt/remnanode`: `.env` с ключом (chmod 600), `docker-compose.yml`, `up -d`
8. проверка: статус контейнера, слушается ли порт, ошибки в логах

В конце сводка и `РЕЗУЛЬТАТ: ok`, либо список проблем и код выхода 1.

## Чего скрипт не сломает

- **Чужой `SECRET_KEY`** — существующий валидный ключ остаётся; перезаписать
  можно только флагом `--force-key`
- **Чужой `docker-compose.yml`** — если в нём есть сервисы кроме `remnanode`
  (nginx, caddy), файл не трогается и контейнеры не перезапускаются: делается
  только базовая подготовка системы
- **Существующий `/etc/docker/daemon.json`** — не переписывается
- Перед записью `.env` и compose кладутся бэкапы `*.bak.<timestamp>`
- Скрипт идемпотентен: повторный запуск ничего не ломает

## Флаги

```
--secret <key>       SECRET_KEY из панели (можно вставить строку SECRET_KEY=...)
--panel-ip <ip>      IP панели; порт ноды откроется только ему
--node-port <port>   порт связи с панелью (по умолчанию 2222)
--hostname <name>    переименовать сервер
--timezone <tz>      часовой пояс (по умолчанию Europe/Moscow)
--dir <path>         каталог ноды (по умолчанию /opt/remnanode)
--last <N>           сколько последних входов показать (по умолчанию 10)
--status-only        только отчёт, ничего не настраивать
--no-status          пропустить отчёт, сразу настройка
--no-upgrade         не обновлять пакеты
--no-ufw             не трогать фаервол
--no-fail2ban        не ставить fail2ban
--no-swap            не создавать swap
--force-key          перезаписать существующий SECRET_KEY
--yes                ничего не спрашивать, брать дефолты
```

Все параметры можно задать и переменными окружения: `SECRET_KEY`, `PANEL_IP`,
`NODE_PORT`, `NEW_HOSTNAME`, `TIMEZONE`, `INSTALL_DIR`, `LAST_COUNT`.

## Требования

Debian или Ubuntu, root. Всё остальное скрипт доставит сам.
