# begleq-autorwnode

Один скрипт для ноды Remnawave: сначала показывает, что на сервере происходит,
потом настраивает его с нуля. Ничего ставить у себя на машину не нужно —
скрипт кладётся на сервер и запускается там.

## Установка одной командой

На сервере, от root:

```bash
curl -fsSL https://raw.githubusercontent.com/beqwes/begleq-autorwnode/main/node-setup.sh -o node-setup.sh && bash node-setup.sh
```

Скрипт останется в текущем каталоге — им же потом удобно перепроверять ноду.

Совсем без файла, сразу в пайп:

```bash
curl -fsSL https://raw.githubusercontent.com/beqwes/begleq-autorwnode/main/node-setup.sh | bash
```

Вопросы читаются с `/dev/tty`, поэтому и через пайп скрипт остаётся интерактивным.
Флаги в этом случае передаются через `bash -s --`:

```bash
curl -fsSL https://raw.githubusercontent.com/beqwes/begleq-autorwnode/main/node-setup.sh | bash -s -- --status-only
```

```bash
curl -fsSL https://raw.githubusercontent.com/beqwes/begleq-autorwnode/main/node-setup.sh | bash -s -- --domain fl.example.tld --panel-ip 203.0.113.10 --yes
```

Повторный запуск той же командой обновляет скрипт и перенастраивает ноду —
существующий ключ и чужой compose при этом не трогаются.

## Запуск

```bash
bash node-setup.sh
```

Спросит `SECRET_KEY`, IP панели, порт, имя сервера и часовой пояс.
Вопросы читаются с `/dev/tty`, поэтому работает и через пайп.

Только посмотреть, ничего не меняя:

```bash
bash node-setup.sh --status-only
```

Без единого вопроса:

```bash
bash node-setup.sh --secret 'КЛЮЧ' --panel-ip 203.0.113.10 --yes
```

## Что делает

**Часть 1 — отчёт о ноде**

- кто и откуда заходил: последние входы, чужие IP помечены звёздочкой,
  последняя перезагрузка, кто в системе сейчас
- неудачные попытки входа и баны fail2ban
- контейнеры: образ, статус, число рестартов, health, время старта
- здоровье ноды: версия образа, слушается ли порт панели, разбор логов
  (mTLS, неверный ключ, старт ядра), число соединений, трафик с загрузки,
  сроки сертификатов Let's Encrypt
- службы с автозапуском и упавшие юниты
- порты наружу: TCP полностью, случайные высокие UDP свёрнуты в одну строку
- ресурсы: аптайм, нагрузка, память, swap, диск с порогами 80 и 90 %

**Часть 2 — параметры**

Подхватывает существующий `SECRET_KEY` и предлагает оставить его.
Сам определяет SSH-порт из `SSH_CONNECTION`, чтобы правилом ufw не отрезать
себе доступ. Показывает сводку и ждёт подтверждения.

**Часть 3 — настройка, 11 шагов**

1. имя сервера, часовой пояс, NTP
2. `apt update` и обновление пакетов, базовый набор утилит
3. swap 2–4 ГБ, если его нет
4. sysctl: BBR + fq, сетевые буферы, `nofile 1048576`
5. docker (ставит, если нет) и ротация логов в `daemon.json`
6. ufw (SSH, 443 tcp/udp, 80 для certbot, порт ноды только с IP панели) и fail2ban
7. сертификат Let's Encrypt на домен ноды + хук перезагрузки nginx при продлении
8. сайт-заглушка: случайная тема, случайное название и палитра
9. `nginx.conf` под self-steal и контейнер `remnawave-nginx`
10. `/opt/remnanode`: `.env` с ключом (chmod 600), `docker-compose.yml`, `up -d`
11. проверка: контейнеры, `nginx -t`, сокеты, порт, логи, сертификат

В конце сводка и `РЕЗУЛЬТАТ: ok`, либо список проблем и код выхода 1.

## Чего скрипт не сломает

- **Чужой `SECRET_KEY`** — существующий валидный ключ остаётся; перезаписать
  можно только флагом `--force-key`
- **Чужой `docker-compose.yml`** — если в нём есть сервисы кроме `remnanode`
  (nginx, caddy), файл не трогается и контейнеры не перезапускаются: делается
  только базовая подготовка системы
- **Существующий `/etc/docker/daemon.json`** — не переписывается
- Перед записью `.env` и compose кладутся бэкапы `*.bak.<timestamp>`
- Скрипт идемпотентен: повторный запуск ничего не ломает

## Флаги

```
--secret <key>       SECRET_KEY из панели (можно вставить строку SECRET_KEY=...)
--panel-ip <ip>      IP панели; порт ноды откроется только ему
--node-port <port>   порт связи с панелью (по умолчанию 2222, спросит при запуске)
--node-version <tag> версия образа ноды, например 3.2.2 или latest
--node-image <ref>   образ целиком, если нужен свой реестр
--domain <host>      self-steal домен: сертификат, nginx и сайт-заглушка
--email <mail>       почта для Let's Encrypt (по умолчанию admin@домен)
--xhttp-path <path>  путь, который nginx отдаёт Xray (по умолчанию /api/v3/media)
--fallback-port <p>  локальный порт для dest у Reality (по умолчанию 9443, 0 — выключить)
--site-theme <t>     тема заглушки: media, files, studio, shop (случайная)
--force-site         перезаписать существующий сайт
--no-nginx           не ставить nginx и не выпускать сертификат
--no-site            не трогать сайт-заглушку
--hostname <name>    переименовать сервер
--timezone <tz>      часовой пояс (по умолчанию Europe/Moscow)
--dir <path>         каталог ноды (по умолчанию /opt/remnanode)
--last <N>           сколько последних входов показать (по умолчанию 10)
--status-only        только отчёт, ничего не настраивать
--no-status          пропустить отчёт, сразу настройка
--no-upgrade         не обновлять пакеты
--no-ufw             не трогать фаервол
--no-fail2ban        не ставить fail2ban
--no-swap            не создавать swap
--force-key          перезаписать существующий SECRET_KEY
--yes                ничего не спрашивать, брать дефолты
```

Все параметры можно задать и переменными окружения: `SECRET_KEY`, `PANEL_IP`,
`NODE_PORT`, `NEW_HOSTNAME`, `TIMEZONE`, `INSTALL_DIR`, `LAST_COUNT`.

## Домен, nginx и сайт-заглушка

Если указать домен, скрипт поднимает ту же схему, что на боевых нодах:

- **Xray сам слушает `:443`**, а nginx сидит на `unix:/dev/shm/nginx.sock`
  с `proxy_protocol` и получает от Xray всё, что не является VPN-трафиком
  (self-steal). Отдельного порта под nginx не нужно.
- `nginx.conf` пишется как фрагмент `conf.d/default.conf`: server-блок на домен,
  `location <xhttp-path>` проксируется в `unix:/dev/shm/xrxh.socket`, а
  default-сервер отвечает `ssl_reject_handshake` и `444` на всё чужое.
- **Сайт-заглушка ставится сама** и каждый раз разный: случайная тема
  (медиа-стрим, файлохранилище, веб-студия, магазин), случайное название,
  случайный акцентный цвет, свои цифры в статистике. Внутри — главная,
  тематический раздел, страница «О нас», CSS с тёмной темой, живой JS,
  favicon, `robots.txt` и `sitemap.xml`. Путь Xray в `robots.txt` не светится.
- Сертификат выпускается `certbot --standalone` (порт 80 в этой схеме свободен),
  ставится хук, который перезагружает nginx после каждого продления.

```bash
bash node-setup.sh --domain fl.example.tld --site-theme shop
```

Без домена nginx, сертификат и сайт пропускаются — поднимется голая нода.
Уже существующий сайт в `/var/www/html` не перезаписывается без `--force-site`.

### Почему заглушка может не открываться

Сайт отдаёт **не nginx напрямую, а Xray** по правилам инбаунда из панели.
Чтобы заглушка открылась, в инбаунде этой ноды должно быть:

- `serverNames` содержит домен ноды — иначе Reality сбрасывает соединение
  с «чужим» SNI, и до nginx оно вообще не доходит;
- `dest` (он же target) ведёт к заглушке: либо `/dev/shm/nginx.sock`
  с `proxyProtocol`, либо `127.0.0.1:9443`.

Скрипт слушает **оба варианта сразу**, так что со стороны сервера подходит
любая схема; порт для второго меняется флагом `--fallback-port`, наружу он
не открывается. Несовпадение скрипт находит сам и пишет прямо в отчёте, что
править в панели.

Сокет `/dev/shm/xrxh.socket` создаёт сам Xray, поэтому он появится только
после того, как панель отдаст ноде конфиг с этим inbound. До этого момента
nginx работает, но :443 ещё никто не слушает — это нормально.

## Версия ноды и ошибка «SSL alert number 40»

Если в логах ноды видно

```
SSL routines:ssl3_read_bytes:ssl/tls alert handshake failure ... SSL alert number 40
```

значит версии ноды и панели разошлись и mTLS между ними не сходится.
Поэтому образ по умолчанию **запинен** на `remnawave/node:3.2.2`, а не `latest`
(latest сейчас 3.3.x и с панелями 2.8.x не работает).

Поменять версию:

```bash
bash node-setup.sh --node-version 3.2.2
```

Скрипт сам предложит текущую версию при повторном запуске, предупредит, если
выбран `latest`, и распознает эту ошибку в логах — и в отчёте при входе,
и после настройки, сразу с подсказкой, чем лечить.

## Порт ноды

Порт спрашивается при каждом запуске. Если нода уже настроена, по умолчанию
подставляется её текущий порт, а не 2222. При смене порта скрипт удаляет
старое правило ufw, чтобы прежний порт не остался открытым, и напоминает
поменять порт в панели. Порт проверяется на диапазон, на совпадение с SSH
и на то, что его не занял посторонний процесс.

## Требования

Debian или Ubuntu, root. Всё остальное скрипт доставит сам.
