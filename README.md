# begleq-autorwnode

Настройка ноды Remnawave одним скриптом. Запускается на самом сервере,
ставить ничего у себя не нужно.

Что делает: готовит систему (пакеты, swap, BBR, лимиты, docker, ufw, fail2ban),
выпускает сертификат Let's Encrypt, поднимает ноду и nginx с сайтом-заглушкой,
проверяет результат и вешает отчёт о состоянии ноды при входе по SSH.

## Установка

На сервере, от root:

```bash
curl -fsSL https://raw.githubusercontent.com/beqwes/begleq-autorwnode/main/node-setup.sh -o node-setup.sh && bash node-setup.sh
```

Скрипт спросит SECRET_KEY, домен, порт и остальное. Повторный запуск ничего
не ломает: существующий ключ и чужой `docker-compose.yml` не трогаются.

## Занятые порты

Перед тем как что-то менять, скрипт показывает порты, которые займёт
(443/tcp и 443/udp под Xray, порт ноды, 80 под nginx, в режиме
CDN — 443, 80 и локальный порт Xray), и кто их сейчас держит:

```
── порты ───────────────────────────────────────────────────────────────────
  ● 443/tcp    Xray: Reality / XHTTP / WS         уже наш (rw-core)
  ● 2222/tcp   API ноды (связь с панелью)         свободен
  ● 80/tcp     nginx: редирект и сертификаты      ЧУЖОЙ: nginx(pid 812)
```

«Наш» определяется по контейнеру процесса (`remnanode`, `remnawave-nginx`),
а не по имени — системный nginx или чужой Xray так не спутать. Если порт занят
чужой программой, в терминале скрипт спросит, продолжать ли (по умолчанию нет),
а с `--yes` остановится, ничего не поменяв. Продолжить всё равно —
`--ignore-busy-ports`.

## Полезные режимы

Только посмотреть состояние ноды, ничего не меняя:

```bash
bash node-setup.sh --status-only
```

Поставить отчёт при входе на уже настроенную ноду:

```bash
bash node-setup.sh --motd-only
```

Без вопросов:

```bash
bash node-setup.sh --secret 'КЛЮЧ' --domain example.com --panel-ip 203.0.113.10 --yes
```

Полный список флагов — `bash node-setup.sh --help`.

## Про сайт-заглушку

Если указать домен, скрипт выпускает сертификат и поднимает рядом с нодой
nginx с сайтом-заглушкой. Заглушка выбирается случайно из **30 пресетов**:
шесть раскладок (тёмный герой, журнальная обложка, чёрно-белый разворот,
зернистый постер, страница персонажа, киноафиша), у каждой пять тем со своей
палитрой — музыкальные жанры, кофе, дизайн-студия, аниме, кино, японские
прогулки, игровые саундтреки.

Контент настоящий: названия роликов, каналы и обложки берутся с YouTube,
все ссылки проверены. Конкретный пресет задаётся флагом:

```bash
bash node-setup.sh --site-theme nexora
```

Заглушку отдаёт не nginx напрямую, а Xray по правилам инбаунда из панели:
в `serverNames` должен быть домен ноды, а `target` — `/dev/shm/nginx.sock`
с `xver: 1` (nginx слушает только этот сокет, отдельный TCP-порт не занимает).
Скрипт сам сверяет эти настройки с панелью.

## Несколько доменов (SNI)

На одну ноду можно повесить два, три и больше self-steal доменов — через
запятую или повтором флага:

```bash
bash node-setup.sh --domain one.example,two.example,three.example
```

Первый домен основной: его сайт лежит в `/var/www/html`, его сертификат
берёт Hysteria2. Для каждого домена скрипт:

- выпускает **отдельный** сертификат, а не один общий: в общем сертификате
  (и в логах Certificate Transparency) домены видны списком, и по одному
  сразу находятся остальные;
- собирает **свой** сайт-заглушку в `/var/www/sites/<домен>` — с другой
  раскладкой и темой, чтобы домены на одном IP не выглядели копиями;
- добавляет свой `server` в nginx и проверяет, что домен есть в `serverNames`
  инбаунда панели.

A-записи всех доменов должны указывать на ноду. Домен, сертификат которого
не выпустился, в nginx не попадает: без файла сертификата nginx не стартовал
бы вовсе и уронил бы заглушку на всех доменах.

В панели: в инбаунде Reality `serverNames` — все домены списком, а в хостах —
по хосту на домен, у каждого свой `sni`.

Добавить или убрать домен на уже настроенной ноде проще всего из меню:
`begleq` → **13** (добавить) или **14** (убрать). Пункт 13 проверяет A-запись,
открывает 80/443 в ufw и выпускает сертификат, не трогая остальное: IP панели,
порт ноды и TrafficGuard. Если сертификат домена раньше не выпустился, там же
по Enter можно попробовать ещё раз.

Если сертификат не выпустился, nginx всё равно поднимается: домен без
сертификата в конфиг не попадает, а порт 80 продолжает отвечать на проверки
Let's Encrypt. В том же прогоне скрипт пробует выпустить сертификат ещё раз
уже через работающий nginx. Порты 80 и 443 должны быть открыты и в фаерволе
хостера: его скрипт открыть не может.

## Продление сертификата

Продлевается само: certbot ставится вместе с нодой, скрипт явно включает
`certbot.timer` (на части систем он приходит выключенным) и переводит продление
на `webroot` — nginx занимает порт 80, и `standalone` на нём падал бы. После
каждого продления хук перезагружает nginx, чтобы он подхватил новый сертификат.

Настройка проверяется сухим прогоном `certbot renew --dry-run` сразу после
установки, а состояние видно в отчёте:

```
ok  сертификат example.com годен ещё 85 дн.
ok  автопродление: способ webroot, таймер active
```

## TrafficGuard

Вместе с нодой ставится TrafficGuard: списки сканеров и сетей госорганизаций
из [traffic-guard-lists](https://github.com/shadow-netlab/traffic-guard-lists)
складываются в ipset, цепочка вешается первой в INPUT, списки обновляются
ежедневно по таймеру и переживают перезагрузку.

Белый список **важнее** блок-листа: разрешённые адреса уходят по `RETURN`
и дальше обрабатываются обычными правилами. IP панели и адрес, с которого
идёт установка, попадают туда автоматически, остальные — флагом:

```bash
bash node-setup.sh --tg-allow 1.2.3.4,5.6.7.8
```

Управление исключениями потом:

```bash
tg-allow add 1.2.3.4 "нода NL"   # добавить и сразу применить
tg-allow test 1.2.3.4            # проверить, блокируется ли адрес
tg-allow list                    # показать белый список
```

То же удобнее из меню: `begleq` → **7**.

- **Проверить IP и разбанить.** Показывает, в бане ли адрес, какой сетью и из
  какого списка, и чья это сеть (AS, организация, город — из подписей в
  списке). Если в бане, сразу предлагает разбанить только этот IP или всю
  сеть и спрашивает подпись для белого списка.
- **Поиск по спискам** — по IP, началу адреса (`95.161.`), AS (`AS8359`) или
  названию организации (`rostelecom`).
- **Белый список** — посмотреть с подписями и убрать запись.
- **Обновить списки** сейчас, не дожидаясь таймера.

Разбан — это добавление в белый список, а не вычёркивание из блок-листа:
списки каждый день скачиваются заново, и вычеркнутый адрес вернулся бы, а белый
список важнее блок-листа и обновлением не затирается.

Отключается флагом `--no-traffic-guard`. Если на ноде уже стоит свой
`traffic-guard`, скрипт его не трогает.

## WARP

Скрипт поднимает Cloudflare WARP отдельным интерфейсом `warp` (wgcf + wg-quick)
и **не трогает маршрут по умолчанию** — `Table = off`, иначе в туннель ушёл бы
весь трафик ноды вместе со связью с панелью. Строка `DNS =` из профиля
убирается: под неё нужен `resolvconf`, а системный резолвер менять незачем.

Готовый outbound скрипт печатает в конце и кладёт в
`/opt/remnanode/warp-outbound.json` — его вставляют в конфиг ноды в панели:

```json
{
  "tag": "warp",
  "protocol": "freedom",
  "settings": { "domainStrategy": "UseIP" },
  "streamSettings": { "sockopt": { "interface": "warp", "tcpFastOpen": true } }
}
```

Дальше в `routing` добавляется правило, что гнать через него, например
`{ "type": "field", "domain": ["geosite:openai"], "outboundTag": "warp" }`.

Поставить WARP на уже настроенную ноду, ничего больше не трогая:

```bash
bash node-setup.sh --warp-only
```

Выключить (профиль остаётся, включить обратно `--warp-only`) или снести совсем:

```bash
bash node-setup.sh --warp-off
bash node-setup.sh --warp-purge
```

В полном прогоне отключается флагом `--no-warp`. После выключения не забудь
убрать outbound `warp` из конфига ноды в панели — иначе Xray будет слать
трафик в несуществующий интерфейс.

## BBR

Включается по умолчанию на шаге с сетевыми лимитами: `bbr` + `fq`, буферы
и `nofile 1048576`. Отдельно на уже настроенной ноде:

```bash
bash node-setup.sh --bbr-only
```

Пропустить в полном прогоне — `--no-bbr`. Текущее состояние видно в отчёте
`--status-only` и в меню `begleq`.

## Yandex CDN

Отдельный пункт: нода становится origin для Yandex Cloud CDN, клиенты ходят
на публичный домен, эджи бьют в origin на `:443`. nginx слушает 80/443, Xray —
только `127.0.0.1:11443` с XHTTP `packet-up`. Reality self-steal на `:443`
с этим режимом не совмещается.

На уже настроенной ноде:

```bash
begleq          # пункт 11
bash node-setup.sh --yandex-cdn
bash node-setup.sh --yandex-cdn --cdn-origin origin.example --cdn-public cdn.example --yes
```

Скрипт спросит origin-домен, публичный домен, путь и порт Xray, выпустит
сертификат Let's Encrypt на origin, перепишет nginx (буферизация и gzip
выключены — иначе восходящий XHTTP рвётся), закроет `:11443` снаружи и
положит полный конфиг Xray в `/opt/remnanode/yandex-cdn-xray.json`
(host = публичный домен, который указали — CNAME на тех-домен CDN).

По умолчанию origin закрывается заголовком `X-Cdn-Secret`: его же надо
прописать в `staticRequestHeaders` ресурса CDN. Как на эталоне, без секрета:

```bash
bash node-setup.sh --yandex-cdn --cdn-open-origin
```

Инструкция для панели и консоли — пункт 12 или `--cdn-show`. Кратко:

- A-запись origin → IP ноды, CNAME публичного домена → `provider_cname`
- в консоли CDN: HTTPS к origin, Host = origin-домен, кеш/slice/Range выкл.,
  query и cookie не выкидывать
- хост в панели: `address` = тех-домен CDN, `host`/`sni` = публичный домен,
  `xHttpExtraParams` = extra из конфига (панель сама не копирует)

## Смена версии ноды

Версия ноды должна подходить к версии панели, иначе mTLS не сходится и в логах
ноды будет `tls alert handshake failure ... alert number 40`. С панелями 2.8.x
работает нода 3.2.2, с более новыми — нода той же версии.

Сменить версию на готовой ноде: `begleq` → **15** или без меню:

```bash
bash node-setup.sh --set-node-version 3.2.2
```

Скрипт меняет только образ ноды в `docker-compose.yml`, пересоздаёт один
контейнер и 25 секунд смотрит в лог. Если тег не скачался или нода поймала
alert 40 — возвращает прежнюю версию сам.

## Меню настроек

После установки на ноде появляется команда `begleq` — открывает меню из любого
каталога: состояние ноды, повторная настройка, WARP включить/выключить/снести,
BBR, исключения TrafficGuard, пересборка заглушки, Yandex CDN, добавление и
удаление SNI-доменов, обновление самого скрипта с гитхаба.

```bash
begleq
```

В шапке меню сразу видно состояние: контейнеры, BBR, WARP, размер блок-листа,
домены со сроком сертификатов и слушающие порты — наши зелёные, системные
серые, а чужая программа на порту ноды (443, 80, порт панели) красная.

## Тесты VPS

`begleq` → **16** — подборка проверок сервера из шпаргалки:

| # | что проверяет |
|---|---|
| 1 | регион IP по геобазам (`ipregion.vrnt.xyz`) |
| 2 | блокировки IP зарубежными сервисами (IP.Check.Place) |
| 3 | доступ к зарубежным сервисам (check.unlock.media) |
| 4 | скорость до РФ и зарубежья, многопоточный iperf3 (`bench.tlab.pw`) |
| 5 | параметры и скорость до РФ и зарубежья, iperf3 (`bench.gig.ovh`) |
| 6 | параметры и скорость до зарубежья (`bench.sh`) |
| 7 | блокировка аудио в Instagram |
| 8 | YABS: процессор, диск, сеть |

Это сторонние скрипты: они скачиваются из интернета и выполняются от root.
Перед запуском меню показывает точную команду и спрашивает подтверждение,
Ctrl+C прерывает тест и возвращает в меню. Скоростные тесты на несколько минут
занимают канал, YABS ещё и пишет на диск — на ноде с пользователями их лучше
запускать в спокойное время.

## Требования

Debian или Ubuntu, root. Остальное скрипт доставит сам.
